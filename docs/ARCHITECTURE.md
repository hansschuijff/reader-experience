# Reader Experience: architecture and decisions

Status: October 2026 (version 0.2.x). Replaces the Dutch "Architectuur v2" of 29 September 2026. The plugin runs on the
author's own sites; there are no external users yet, so renames and breaking changes are still cheap (keep them in their
own commits).

## Goal

Make long articles (8,000 to 12,000 words) more pleasant to read and invite interaction. One plugin, built for a block
theme, with small blocks on top of PHP services.

## Principles

- **Standalone.** The plugin starts itself on `plugins_loaded`; it needs nothing from the core plugin (`core-functionality-oop`).
- **Blocks are a thin view layer.** Storage and logic live in PHP services, so a widget or shortcode could reuse them.
  Blocks never write to the database themselves.
- **Privacy.** No IP addresses in the database, no personal data in counters. Where a fingerprint is needed for rate
  limiting (IP + user agent) it is hashed and kept briefly in a transient, never in a table.
- **Caching.** Pages may be cached, so dynamic data arrives through REST and JS. Anonymous POST requests use a honeypot,
  a length limit and rate limiting instead of nonces.
- **Follow the theme.** No hard-coded colours. Buttons use `wp-element-button` and zero-specificity `:where()` defaults,
  so theme settings (Styles, Blocks, Buttons) win. Colours chosen in block settings pass through `Support\CssValue`.
- **Small configuration surface.** Order and on/off per child block; the rest is fixed or a filter.
- **No assumptions about outside systems** (core, other plugins) without checking what they actually offer.

## Naming

| What | Convention |
|---|---|
| PHP namespace | `ReaderExperience\`, PSR-4 under `src/`, snake_case methods, `use function` imports |
| Text domain | `reader-experience` |
| Hooks | `reader_experience/<name>` |
| REST namespace | `dewitteprins/reader-experience/v1` (vendor in the namespace) |
| CSS classes, CSS variables | `dwp-rx-…`, `--dwp-rx-…` |
| Data attributes / dataset | `data-dwp-rx-…` / `dwpRx…` |
| Tables, transients, nonces, query args | `dwp_rx_…` (tables: `{prefix}dwp_rx_feedback`, `{prefix}dwp_rx_share_daily`) |
| Block names | `reader-experience/<slug>` |

Until October 2026 the short prefix was `rx` / `rx_`; `Support\Migrations\RenameLegacyTable` renames the old tables.

## Structure

```
reader-experience/

│   ├── Blocks/BlockRegistrar.php  registers shared styles (dwp-rx-base, dwp-rx-toc), blocks from build/blocks, script translations
│   ├── Rest/AbstractController.php

│   └── Modules/
│       ├── Reading/   ReadingModule, ReadingTime, HeadingAnchors, HeadingIndexer, AnchorRegistry, HeadingLinkAssets
│       ├── Bar/       BarModule (interaction-bar, comments-link, toc-open, custom-link)
│       ├── Sharing/   SharingModule, ChannelRegistry, ShareRepository, ShareController, Migrations/
│       └── Rating/    RatingModule, RatingService, FeedbackRepository, RatingController, CommentPublisher, Notifier,
│                      Migrations/, Admin/ (PostColumn, DashboardWidget, FeedbackPage)
├── blocks/                        reading-time, reading-progress, resume-reading, toc, interaction-bar, comments-link, toc-open, custom-link, share,
│                                  rating; shared/ (toc.js, popover.js, article-progress.js, icons.js)
```

Modules implement `ModuleInterface` (`id`, `register`, `blocks`, `migrations`) and can be added or removed with the
filter `reader_experience/modules`.

## Decisions

| Topic | Decision | Reason |
|---|---|---|
| Resume reading | Position in `localStorage` only, per post; a block with a hidden notice that the script shows | Needs no server, no counters and no personal data; works with page caching |
| One plugin, internal modules | Reading tools and interaction together | Blocks bring a JS build and change more often than the core; a split is possible later along reading / interaction |
| Share counts | Not shown | Facebook and X no longer provide public counts; low numbers backfire |
| Share clicks | Counted per channel per day, visible in admin only | Shows which channels are alive; it measures clicks, not completed shares |
| Sharing UI | `navigator.share()` on mobile; popover with channels and a copy field on desktop; plain links without JS | Native menu needs no upkeep |
| Rating | Like / dislike. A like can add a comment (optionally published as a WordPress comment); a dislike can ask for contact details | Stars are subjective; free text is the most useful feedback |
| Feedback token | Only a sha256 hash in the database; expires after 30 minutes and is cleared after use | Nobody but the sender can attach text later |
| Spam protection | Honeypot, text length limit, fixed-window rate limiter (off for `local` / `development` environments) | No nonces on cached pages; no IP storage |
| Throttled requests | Silent fake success | Nothing leaks about the spam detection |
| Public display | No public negative counts | Negative social proof |
| Interaction bar | Container block with fixed allowed children; hides on scroll down on mobile, always visible on desktop; no transform while visible | A transformed ancestor becomes the containing block of fixed panels |
| Bar panels | One panel open at a time through `blocks/shared/popover.js` and DOM events (no Interactivity API) | Pragmatic; can migrate later |
| Comments | Existing WordPress comments; the bar shows the count and jumps to the comments, the form or an own anchor (setting; automatic by default: comments when there are any, otherwise the form) | No system of our own |
| Table of contents | Built in the browser from h2 to h4: headings get `data-dwp-rx-heading="<n>"` (index based), independent of heading ids and anchor links | Robust against text edits; works with anchor links off. Without JavaScript the block does not show |
| Contents button | Opens the list in a side panel (`<dialog>`): non-modal and pushing the page aside from 1100px, modal overlay with a history entry on phones (back button closes it). Attributes: title, side, levels, minimum headings, collapsible sub-levels, statistics, display (beside the page or over it) | Like the editor's list view; the page stays fully visible |
| Custom link | Bar child with a label, URL (web, mailto, tel, relative or #anchor; anything else renders nothing), one of thirteen icons (or the class of an icon font such as Font Awesome, chosen from the same list) and an optional new tab. Icon only in the bar; the label is the tooltip and the screen reader text | A permanently visible way to point readers to help or contact |
| Inline TOC block | Stays available for sidebars, widget areas and navigation | The panel is tied to the bar; the block is the standalone variant |
| Heading anchors | Off by default. `AnchorRegistry` hands out ids: from the text, unique per post, reserved ids (comments, respond, content, ...) get the level in front (`h2-comments`); filters `heading_anchor_id` and `reserved_ids`. Only for the post the visitor asked for (`is_singular()` and the queried id), not for posts shown inside other pages. Copy-link icon via own JS/CSS | Links must never land on theme or comment elements. TOC does not depend on it |
| Translations | `.pot/.po/.mo` plus Jed JSON for editor scripts; `LocaleFallback` for installs where the text domain does not load; a debug log under `WP_DEBUG` | Seen in practice on one site |
| Filter labels | Missing or empty labels fall back to the translated default, with `_doing_it_wrong()` under `WP_DEBUG` | Makes a forgotten label easy to find |
| Migrations | Own small `Migrator` (option with executed ids), runs on activation and in admin | No migration system available |
| Admin | Feedback page under Comments ("Reader feedback"): table, filter by post, bulk delete via POST + nonce + `moderate_comments`; post column; dashboard widget | Small scope; no `WP_List_Table` yet |
| Dark mode | Owned by the theme, not by this plugin | Site-wide presentation |

## Not doing

Recognition questions ("do you recognise this?") after an article: too blunt for the intended tone; recognition should come
from the writing. Share counts, star ratings, public thumbs-down, a free-form bar builder, a word counter for visitors (statistics in the
panel are optional and per block).

## Data

| Table | Columns | Purpose |
|---|---|---|
| `{prefix}dwp_rx_feedback` | id, post_id, value (`like` / `dislike`), text, token_hash, token_expires, contact_name, contact_email, created | Every rating with optional comment and follow-up |
| `{prefix}dwp_rx_share_daily` | id, post_id, channel, day, count (unique on post_id + channel + day) | Daily counter per channel, upsert |

Totals are computed with `GROUP BY`, not cached in post meta.

## REST (`dewitteprins/reader-experience/v1`)

- `POST /rating`: create a rating; returns `{id, token}`. Spam or throttling returns an invented id without storing anything.
- `POST /rating/{id}/text`: attach the explanation (token required); always answers 204.
- `POST /rating/{id}/follow-up`: publish the comment (like) or leave contact details (dislike); token required.
- `POST /share`: count a share click (`sendBeacon`); an identical recent click from the same fingerprint is a silent 204.

## Filters

`reader_experience/modules`, `share_channels`, `words_per_minute`, `icons`, `can_publish_as_comment`, `notify_on_feedback`,
`rating_spam_check`, `rate_limit_enabled`, `heading_anchors_enabled`, `heading_anchors_post_types`,
`heading_anchors_load_css`, `heading_anchors_load_js`, `heading_anchors_config`, `heading_anchor_id`, `reserved_ids`. See the README for details.

## Testing

Checks that run without WordPress: `php -l`, phpcs (WordPress standard), regression scripts with hand-written WordPress
stubs, `npm run build`, and Chromium checks on static pages built from the real CSS/JS. The plugin has been used on the
author's development sites; the editor behaviour of the blocks and theme interaction (Twenty Twenty-Five, Genesis child
themes) are verified there by hand. There is no automated integration test against a real database or REST server.

## Open points

- Planned: previous/next article navigation.
- Scroll depth analytics with a privacy-friendly tool (events for the tool of choice, such as Hotjar, once consent is
  settled); read-aloud only if asked for.
- `GET /state` or a REST refresh of the comment count if cached pages show stale numbers.
- Which share channels make sense (now WhatsApp, LinkedIn, Facebook, email; extend with `reader_experience/share_channels`).
- Possibly turn `FeedbackPage` into a `WP_List_Table` (sorting, filtering).

## Working agreements

- Answer in Dutch in the conversation; code and comments in English; the site itself is Dutch with nl_NL translations.
- Small steps, small separate commits, delivered as patches (`git format-patch`, applied with `git am`, then `npm run build`).
- State what is not tested. Verify before calling something done.
- PHP 8.1+, `declare( strict_types=1 );`, WordPress coding standard, no hard-coded colours, no IP storage.
